### Idioms learned (sk-01, sk-02)

- **Never let a large `Nat` literal reach the checker**: `Nat.add(65536n, x)`
  overflows its stack (unary). Parametrize by the base; instantiate at the top.
- A def used above its definition is treated as an unfilled law ("live code
  cannot use it"): helpers first.
- `&k: A -> B` pairs are affine `Type`; write `Sigma<&2, &2, A, k => B>` for a
  reusable `Data` proof object. Destructure with `(+k, e) = h`.
- Python `%` formatting collides with Bend's `%e :` rewrites in generator
  scripts: use `@@name@@` placeholders or concatenation.
- `%e : P` replaces the *right* side of `e` at the `_` holes with its left
  side, so lemmas are stated `{target == source}`. When the wrong side is in
  the goal, rewrite the other side of the goal or use `Equal.sym`.
- `ring_eq(env, target, source, {==})` is itself a rewrite: `%R.ring_eq(...) : P`
  rearranges a subterm. Write motives with `E.eval(env, expr)` to keep them
  short (the checker normalizes).
- Define spec ops via projections (`Q.num(x)`) rather than matching, so they
  compute on symbolic arguments.
- Refute `{0n == 1n+k}`-style hypotheses with a type-picking motive
  (`NatD(_, Unit, Goal)`): the motive must be the goal at e's right side.
- Mechanical case proofs can be generated by a scratch script; Bend checks
  the output. Put helpers above callers; write `1n++k` when a predecessor is
  reused.

### sk-03 lessons

- **Generic proofs use template parameters.** A law `for ~F: OField` (a
  record of carrier, ops and axioms) is checked with F opaque (`law~F` in
  errors), and its axioms may be used any number of times. Plain or erased
  function-valued parameters do not work: plain ones are affine (one use),
  erased ones cannot appear in a proof term, not even inside a `%` rewrite.
  Accessors: `O.add(F, a, b)`, laws `O.add_comm(F)(a, b)`; derived defs take
  `~F` (`O.sub(~F, a, b)`). Filling a template law: `def name(F, x, ..)`.
- Multi-line constructor fields and parametric data (`type V2<-A: Data>`) work;
  `def Vec(~F) -> Data: V2<O.C(F)>` works as a type alias.
- A let-bound constructor needs an annotation: `+x = {E.QMul{..} : E.QExpr}`.
- `is` is a keyword. Refuting `{Zpos.. == Z0}` vs `{Z0 == Zpos..}` needs the
  motive matching the *right* side's constructor (`nz`/`zn` in the demo).
- A wrong demo constraint is found fast by running a per-constraint `List<Bool>`
  as `main` (`bin/bend f.bend`, no `--check-only`).
- **One match per def** when a match uses nested constructor patterns
  (`K.Seg{K.Pt{..}, ..}`): a second match in the same def fails with "a
  match on a parameter or field (... consumed binder)". Split into helpers
  (`Angle.sound` → `Angle.sound.r`).
- A computed value cannot be destructured (`(a, b) = f(x)`): pass it as a
  parameter to a helper def that destructures it.
- Components of `&` pairs (and `Exists`) are single-use even when their
  type is Data; a def whose declared return is `Type` gives single-use
  values. Make reusable facts `Data` (`lt`, `le`, `Both`, `Zeros`, `Sides`)
  or pass them once to a helper with a `+` parameter of explicit Data type.
- A template may call only templates defined above it (same as defs).
- Certificates: write the relation shapes exactly as the goal normalizes
  (`O.sub(~F, a, b)` unfolds to `add(a, neg b)`; `O.two` to `1 + 1`); the
  normalizer call is checked by computation, so a wrong coefficient fails
  fast with the leftover normal form.

### sk-04 lessons

- **Signs beat comparisons.** An order fact on ℤ or ℚ is a ring identity on
  a difference plus a sign: `pos(Zpos p + Zpos q)` computes, so
  transitivity, monotonicity and cancellation are one normalizer call and a
  case split (`lib/zord.bend`, `lib/qord.bend`).
- **Inequalities in F are certificates too:** write the slack as a sum of
  products of nonnegatives and match it by one `@ZEQ` (|ab| ≤ st: twice
  st ∓ ab is (s ∓ a)(t ± b) + (s ± a)(t ∓ b)). Halve with `twice_nonneg`.
- **Lists with trailing zeros** make linear algebra shape-free: vadd pads,
  dot truncates, and every identity is exact list equality.
- **Untrusted computation, checked answer:** `q_reduce` proves nothing about
  gcd; it multiplies back. Use this whenever a proof of the algorithm is not
  the point.
- **Canonical forms by construction:** Stern–Brocot words make uniqueness of
  lowest terms structural (no Bézout). Encoding with unary fuel n + d keeps
  the fuel argument trivial (each step drops n + d by at least 1).
- **A fallback `case x y z:` leaves the scrutinee abstract**, so a function
  matched the same way does not reduce in that branch: split into one match
  per parameter with every case explicit (`reduce.fin`, `reduce.fin2`, ...).
- **Rewrite order matters inside a goal:** rewrite the parts the next
  rewrite's right side mentions first (`enc_ratio`: the comparison before
  the induction hypothesis).
- Pattern variables reused in proof terms need `+` (`Con{+x, +xs}`,
  `1n++f`), including in multi-scrutinee matches.
- An `OField` record is built with lambdas for every field
  (`a => b => add(a, b)`, axioms likewise); Bend checks each axiom against
  the operations given (negative-tested in sk-04).
